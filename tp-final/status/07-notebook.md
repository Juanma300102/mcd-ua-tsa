# Phase 07 — Deliverable notebook consolidation

Status: done

## Objective

One clean notebook that runs end to end and contains all the analysis per series.

## Constraint

Each group member uploads at most 2 files: the PDF report and one script/notebook. The deliverable must therefore be a single notebook (working notebooks per phase may exist, then get consolidated). The professor never sees the repository, `tsa_final/` or `results/` — the notebook must be self-contained (no `import tsa_final`) and its saved outputs must show the whole analysis without necessarily re-running it.

## Tasks

- [x] 07.1 Decide layout: shared helpers at the top (module code inlined, namespace-shims for the three qualified-import submodules), then one section per phase (01-06) with per-series subsections (ALB, store-service), a placeholder section for the teammate's series, and a conclusions section. Route declared: delegated-direct (single writer, no SDD) — the generator script is the one non-trivial artifact, and the notebook itself is its deterministic output, not hand-written.
- [x] 07.2 Merge phase notebooks; remove dead cells; keep outputs (figures, tables) rendered. Not a literal cell-by-cell merge: the generator condenses and rewrites the narrative/code from `notebooks/0[1-6]_*.ipynb` (read in full) into a leaner, faithful equivalent — same calls, seeds and budgets, fewer exploratory/print-only cells.
- [x] 07.3 Cache heavy training results (or reduce epochs/trials) so a full run is feasible. Solved with a `REENTRENAR` switch (default `False`): every phase reads its own `results/0X_*.csv` by default; `REENTRENAR = True` re-runs the real training (same `tsa_final` calls, seeds, budgets as the phase notebooks) and overwrites those CSVs. Tables/rankings/selection/consistency/sensitivity are always recomputed in the notebook from whichever tables are on disk, regardless of `REENTRENAR`.
- [x] 07.4 Restart-and-run-all check; record total runtime. `04_dl_models.ipynb` was re-executed by the orchestrator in the background (GPU) while this phase's code was being written (see Evidence); its `04_dl.csv`/`04_dl_seeds.csv` were restored to the committed (best-weights-corrected) values before this notebook's own execution, so the deliverable notebook itself never needed to re-run the DL training to pick up the fix.
- [x] 07.5 Export figures used by the report to `tp-final/informe/figuras/`. Reinterpreted: the deliverable notebook never writes to `informe/figuras/` (explicit constraint) — every figure is either computed fresh, inline, from cached tables/data (cheap: EDA, rankings, scatter, final forecast) or, for the handful that would otherwise need a non-trivial refit under the default `REENTRENAR = False` (phase 03 SHAP, phase 05 best-model test overlay, phase 06 four-role test overlay), displayed by reading the already-existing PNG in `informe/figuras/` with `IPython.display.Image` (read-only).
- [x] 07.6 Integrate the teammate's series section. Not available yet — Section 3 is an explicit `PENDIENTE` placeholder with the same subsection skeleton as ALB/store-service and a worked example of how to register a new series in `SERIES_REGISTRY`/`SERIES_NAMES` so no other code changes are needed once the data exists.

## Decisions

| Decision | Reason | Discarded alternative |
|---|---|---|
| Self-containment via namespace-shims (`_data`/`_baselines`/`_hybrid` as `types.SimpleNamespace`) plus stripping import lines, instead of rewriting every qualified call site (`_data.X()` → `X()`) | Touches only import lines (11 lines across 5 files) and adds 3 small shim cells, versus rewriting dozens of call sites across 7 files; easier to verify by inspection that behaviour is unchanged (every qualified reference is byte-identical to the original package code) | Rewriting every `_data.X`/`_baselines.X`/`_hybrid.X` call site to a bare name — more text surgery for the same result, and each rewritten call site is a place a manual/regex edit could silently break |
| Two real name collisions fixed with targeted renames: `MSTL` (`baselines.py` imports StatsForecast's `MSTL`; `hybrid_models.py` imports statsmodels' `MSTL` under the same name — renamed to `_SF_MSTL` in `baselines.py`, verified with a literal replace that skips the unrelated `forecast["MSTL"]` column-name string) and `_exog`/`_future_exog`/`_window_features`/`_EXOG_DTYPES` (defined independently in both `ml_models.py` and `hybrid_models.py` — renamed to `_ml_*`/`_hy_*`) | Invisible inside the original package (each module has its own globals); once flattened into one notebook namespace the second module's definition would silently shadow the first's, and any later call into the first module's own functions (global lookup happens at call time) would execute the wrong implementation. Verified by executing every inlined module in one namespace and calling `mstl_arima_fit`, `_ml_exog`, `_hy_exog` directly (see Evidence) before writing any narrative cells | Ignoring the collision on the assumption it is harmless — false for `MSTL` (two genuinely different classes) and risky for the private helpers (near-identical but not guaranteed identical, and any future edit to one could silently affect the other) |
| `REENTRENAR` switch, default `False`, reading `results/0X_*.csv`/`06_final_forecast.csv`; downstream tables/figures/selection always recomputed from those tables regardless of the switch | Keeps the default run inside the ~10-minute budget (measured: ~4-5 minutes) while the code path for real training exists, is faithful (same calls/seeds/budgets as the phase notebooks) and is exercised by inspection/compile-check, not skipped or stubbed | A notebook that always retrains (infeasible to grade/re-run in reasonable time, ~60-70 min estimated) or one that never retrains (would not satisfy "runs the real training through the inlined functions exactly as the phase notebooks did") |
| For 3 figures that need either persisted state not saved to any CSV (phase 03 SHAP needs the winning model's *tuned* hyperparameters, only known in memory when `REENTRENAR = True`) or several non-trivial refits (phase 05's ensemble winner test-forecast; phase 06's four-role 105h test overlay, both involving an `auto_arima`/SARIMA-class refit at ~1 minute each): display the existing `informe/figuras/*.png` via `IPython.display.Image` when `REENTRENAR = False`, compute fresh when `True` | Keeps the default runtime low without fabricating a different figure or silently omitting reportable evidence; every other figure in the notebook (EDA, all validation-MASE rankings, the val-vs-test scatter, the phase 02/04 test-forecast overlays, the final 48h forecast) is computed fresh from cached tables/data because it is cheap (seconds) or a single quick refit (~10-30s per DL architecture, phase 04) | Refitting everything always (blows the runtime budget on every default run) or dropping these three figures from the notebook (loses report-consistency evidence for no runtime reason) |
| `DATA_DIR`/`RESULTS_DIR` (originally `Path(__file__).resolve().parent.parent / "..."`) rewritten to point at the notebook's own `RUTA_DATOS`/`RUTA_RESULTADOS` config variables | A notebook code cell has no `__file__`; the config cell already exposes exactly this kind of overridable path, matching the `Path.cwd().parent / "..."` convention every phase notebook already used | Hardcoding an absolute path (breaks if the notebook or repository moves) |
| Generator (`tp-final/scripts/build_deliverable_notebook.py`) reads `tsa_final/*.py` from disk at generation time (via `pathlib`) instead of embedding module source as string literals in the generator | Avoids re-typing/duplicating ~21 KB of real module code by hand into the generator (error-prone, and the two would drift); a module edit only needs a re-run of the generator, not a hand-sync | Copy-pasting each module's source into the generator as a string literal — guaranteed to drift from `tsa_final/*.py` the first time either changes |

## Evidence

- Generator: `tp-final/scripts/build_deliverable_notebook.py` (~500 lines). Deliverable: `tp-final/entrega/TP2_Series_Temporales.ipynb`, 85 cells (43 code, 42 markdown).
- **Inlining correctness, verified before writing any narrative content**: executed all 7 transformed modules (`data`, `evaluation`, `baselines`, `ml_models`, `dl_models`, `hybrid_models`, `selection`) in one shared namespace, in order, then: loaded `alb` via `load_clean`, ran `evaluate(seasonal_naive_m24, ...)` and got val MASE `0.489260` / test MASE `1.990087` (matches `results/02_baselines.csv` and the report's 0.489/1.990 exactly); called `mstl_arima_fit` end-to-end (confirms the `MSTL`→`_SF_MSTL` rename in `baselines.py` did not break it, and that it still resolves the StatsForecast class, not statsmodels'); called `_ml_exog(...)` and `_hy_exog(...)` directly (confirms the ml_models/hybrid_models rename avoided the collision, both work independently).
- **Self-containment**: `rg -n "tsa_final|from \.|import \."` on the executed notebook shows matches only inside markdown cells, code comments, and one unrelated string literal (`tempfile.mkdtemp(prefix="tsa_final_darts_")`, a temp-dir name, not an import). A programmatic check (regex over every code-cell line, ignoring comments) for `from .`, `import tsa_final`, `from tsa_final` finds zero matches.
- **Execution (`REENTRENAR = False`, the shipped state)**: `jupyter nbconvert --to notebook --execute --inplace` → exit 0, wall time **272 s (~4.5 min)**, zero error outputs across all 43 code cells. Well inside the ~10-minute target.
- **`REENTRENAR = True` run**: **not performed** — it does not "fit easily". Estimated total, summing the phase notebooks' own measured runtimes (`status/02-evaluation-baselines.md`: ~5.3 min; `status/03-ml-models.md`: ~3.3 min; `status/04-dl-models.md`: ~28 min fit / ~31 min notebook; `status/05-hybrid-automl-foundation.md`: ~17.4 min fit / ~21.7 min notebook; phase 06's own handful of refits, a few minutes): **roughly 60-70 minutes** end to end. The code path is present and was compile-checked (`compile()` on every code cell, 0 syntax errors) and reviewed by inspection against the real phase notebooks (same calls, seeds, `n_trials`, budgets), but not executed as part of this phase.
- **Consistency check** (deliverable notebook output vs. `results/06_all_models.csv` vs. `informe/secciones/04-analisis.tex`): ALB selected `auto_arima`, val MASE 0.475 / test MASE 2.058, improvement vs. TP1 SARIMA +48.5%/-34.9%, vs. `seasonal_naive_m24` +2.9%/-3.4% — all match exactly. store_service selected `seasonal_naive_m24` itself, val MASE 0.480 / test MASE 1.443, improvement vs. TP1 SARIMA +25.8%/-1.2% — matches exactly. Best DL by validation MASE: `nhits` (ALB), `nbeats` (store_service) — matches the post-correction numbers in `status/04-dl-models.md`.
- **No stray directories**: `git status --short` after execution shows no `AutogluonModels/`, `lightning_logs/`, or `catboost_info/` anywhere in the repo, and no changes to `results/*.csv`, `notebooks/*.ipynb`, or `informe/figuras/*` (all three are read-only from this notebook's perspective when `REENTRENAR = False`).
- The background re-execution of `notebooks/04_dl_models.ipynb` (GPU, best-weights correction) that was in progress when this phase started finished during this phase's work; its `results/04_dl.csv`/`04_dl_seeds.csv` were restored to the committed values (only 4 TFT rows differed, from GPU non-determinism) before this notebook's own execution — no action was needed from this phase beyond waiting for it and re-checking `git status` on `results/`/`notebooks/` before running `nbconvert`.
